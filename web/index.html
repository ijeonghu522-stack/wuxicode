왜

한 가지 결함에서 세 가지 증상

모델의 응답이 끝나야 도구를 건드리는 구조라면, 아래 세 가지는 어쩔 수 없는 결과입니다.

01

스트리밍이 읽기 도구에서 멈춘다

파일 하나를 읽는 동안 UI가 얼어붙습니다. 사용자는 죽은 프로그램으로 오인하고 Ctrl+C를 누릅니다.

— 응답 완료를 기다린 뒤 도구 실행

02

오래된 캐시

파일을 고쳤는데 에이전트가 옛 내용을 다시 읽고, 그 위에 덮어씁니다. 재시작하면 고쳐진다는 사실을 알게 되는, 조용하고 악질한 실패.

— 시간 기반 만료, 또는 만료 없음

03

컨텍스트 폭발

긴 세션이 요약도 없이 컨텍스트 창에서 죽습니다. 무슨 일이 있었는지 아무도 모릅니다.

— 무손실 잘라내기

해결

세 가지 수정

1

스트리밍과 읽기가 동시에 돌아갑니다

에이전트 루프는 모델이 토큰을 내보내기 시작하면 곧바로 디스크를 만집니다. 읽기 전용 도구(read, grep, glob, ls, git_status, git_diff)는 요청되는 즉시 병렬로 실행되고, 결과만 주입 지점에서 합쳐집니다.

쓰기는 절대 병렬로 돌지 않습니다. docs/adr/0002-toolscheduler.md

0ms모델 토큰 수신
0msread ×4 병렬 시작
33mstest_learn.py
36msrouter.py
38msprovider_store.py
41mskey_validator.py
…모델 계속 수신 중

UI가 멈추지 않는다

2

캐시 무효화가 git를 아는 방식입니다

캐시 키는 다섯 축으로 구성됩니다.

  • tool 도구 이름
  • schema_version 출력 형식 변경 시 bump
  • canonical_args 정규화된 인자
  • HEAD sha + .git/index mtime 두 축 모두 필요
  • (mtime_ns, size) 대상 파일

이 튜플의 한 바이트라도 바뀌면 재계산됩니다. TTL도 없고 "재시작하시겠습니까"도 없습니다. 

// 두 git 축이 모두 필요한 이유
git add    → index mtime만 움직임
git commit → HEAD sha만 움직임

// 둘 다 있어야 git add
만으로 캐시가 무효화됩니다
3

컨텍스트 압축이 앵커를 붙입니다

오래된 도구 결과는 모델이 요약합니다. 경로, 줄 범위, 내용 해시를 그대로 보존하므로 무언가가 조용히 잘려 나가는 일이 없습니다. 열려 있거나 편집 대기 중인 파일은 압축 대상이 아닙니다.

read_filepython/wx/llm/router.py:45-92a3f9c1e2
bashpytest → 68 passed7d0b41aa
grepgil_scoped_release × 61c9e55f0

해시가 없으면 복구할 수 없다

아키텍처

C++는 계산하고, Python은 결정합니다

경계는 엄격합니다. C++은 모델을 고르지 않고, 도구 호출을 정렬하지 않고, OpenAI 스키마를 파싱하지 않습니다. docs/adr/0001-sse-boundary.md 

wx (Python 3.10+)                 wxcore (C++20, pybind11)
├─ agent/    loop, scheduler       ├─ net/   SSE parser (바이트 단위 상태 기계)
├─ llm/      providers, router     ├─ cache/ LRU, ToolCache, GitProbe
├─ tools/    registry, impls       ├─ text/  token counter
├─ context/  assembly, budget      └─ sys/   console, proc stats
└─ ui/       brand, banner
조각언어그 이유
SSE parserC++임의의 청크 경계에서 정확성을 유지하는 건 상태 기계의 일이고, 매 토큰마다 뜨거운 경로에 놓여 있습니다
Tool cacheC++mtime + git revision 프로브는 syscall 바운드입니다. LRU 정책은 무료여야 합니다
Token counterC++메시지 조립마다 호출됩니다. 거기에 파이썬 루프는 지연 급변입니다
Agent loop, 도구, 정책Python자주 바뀌고, 언어의 반복 속도가 개발 속도가 됩니다

다운로드

Windows 단일 실행 파일

파이썬 설치 없이, 의존성 설치 없이. 네이티브 코어까지 번들에 들어 있습니다.

WUXICODE.exe 약 21 MB
  • 단일 파일, 콘솔 서브시스템
  • 아이콘 16–256px, 파일 속성 버전 자동 생성
  • _wx_core 번들됨
  • 시작 시 %TEMP%로 해제 (2–4초)
# Powershell
powershell -ExecutionPolicy Bypass -File scripts\build_exe.ps1

# 실행
.\dist\WUXICODE.exe --doctor

# 모델 등록
ollama create wx-1 C:\models\wx-1-q4.gguf

# 주소 지정
$env:WX_LLM_BASE_URL = "http://127.0.0.1:11434/v1"

.\dist\WUXICODE.exe

빌드

직접 빌드하기

Python 3.10+, CMake 3.24+, MSVC Build Tools. 전체 과정 5분.

1

네이티브 코어 빌드

git clone https://github.com/ujin/WUXICODE
cd WUXICODE
pip install -e .

_wx_core가 site-packages에 설치됩니다. 이게 없으면 토크나이저와 SSE 파서만 비활성화되고 나머지는 동작합니다.

2

아이콘 생성

pip install pillow
python scripts\make_icon.py

# assets/logo.svg → icon.ico + PNG

cairosvg가 있으면 SVG를 그대로, 없으면 Pillow로 같은 그림을 다시 그립니다. Windows에서 cairosvg는 네이티브 DLL이 필요하기 때문입니다.

3

EXE

powershell -ExecutionPolicy Bypass `
  -File scripts\build_exe.ps1 -Clean

# dist\WUXICODE.exe

스크립트가 빌드 후 자동으로 --version과 --doctor를 돌려 네이티브 코어까지 확인합니다.

릴리스 전에

python scripts\check_version.py   # 버전 3중 일치 확인
pytest                            # 68 passed
ruff check python --select F,E9,B
